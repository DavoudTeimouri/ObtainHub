What is ObtainHub WebUI?

            

              
ObtainHub WebUI is a browser-based interface for the ohub command-line tool. It lets you manage installed applications, check for updates, install new software from GitHub, configure settings, and view downloads — all without touching the terminal.

              
Start the WebUI: ohub webui — your browser opens automatically at http://127.0.0.1:8080 (or the port shown in your terminal).

              
Port already in use? ohub picks the next free port (8081, 8082, …). A second ohub webui detects the running instance and opens the existing one instead of starting a duplicate.

Apps Page

            

              
The Apps page has sub-tabs for each action:

              

                
Sub-tabWhat it does

                
                  
Managed AppsLists every app under ObtainHub management. Shows version, status, and whether an update is available. Per-app buttons: Check, Update, Uninstall, Remove.

                  
Find & InstallSearch GitHub repositories. Shows stars, language, last release time, and install status badge (Installed / –). Install or Manage button per result. Results are sortable by stars.

                  
SourcesManage manifest sources (URLs to search for packages). Add or remove sources.

                  
Add to ManagementRegister an existing app under ObtainHub management. Choose type: GitHub repository, ZIP archive URL, Local folder (scans for executables), or Single executable (creates a shim).

                
              

              
Update badge: If ohub check found a newer release, the Update column shows Update available → v2.5.0 with the new version number. Run "Check All Updates" to refresh.

            

          

        


        
        

          

            
Config Page

            

              
All configuration values are editable:

              
    
                
  • Install Dir, Download Dir, Shim Dir — filesystem paths
    • 
                
  • Proxy — HTTP proxy URL
    • 
                
  • HTTP Retries, Retry Delay (ms), Retry Backoff — network retry behavior
    • 
                
  • Bandwidth Limit (B/s) — download speed cap
    • 
                
  • Parallel Downloads, Timeout (s) — concurrency and timeouts
    • 
                
  • Auto Cleanup, Verify Checksums — checkboxes
    • 
                
  • Schedule Enabled, Interval (h), Notify on Update, Run on Startup — scheduled checks
    • 
                
  • Update Check Interval (h) — how often to check for updates
    • 
              

              
Click Save Changes to send PUT /config and persist your edits.

              
Read-only sections: Groups and Token Source are shown as plain text (not editable).

              
GitHub Token: Add a token for authenticated GitHub API access (higher rate limits, access to private repos). Configured token shows as green.

            

          

        


        
        

          

            
Downloads Page

            

              
Shows active and completed downloads with:

              
    
                
  • Download ID and URL
    • 
                
  • Status badge (pending / completed / failed)
    • 
                
  • Progress bar with percentage
    • 
                
  • Bytes downloaded / total
    • 
                
  • Transfer speed and ETA
    • 
              

              
The page auto-refreshes every 2 seconds while you're on it. Use the Download form to start a new manual download (URL, destination, optional label and token).

            

          

        


        
        

          

            
Authentication

            

              
When ohub is started with --auth, the WebUI requires a GitHub token before mutating actions (Check, Update, Uninstall, Remove, Config save).

              
    
                
  • Sign in as current user: Uses Windows admin credentials via PowerShell.
    • 
                
  • Use GitHub token: Paste a personal access token. Token is stored in config and shown as configured (green).
    • 
                
  • Remove token: Clears the stored token and locks mutating actions again.
    • 
              

              
If PowerShell is unavailable on your machine, use the GitHub token instead: ohub config set github_token <token>

              
When auth is not required (no --auth and no token configured), all pages and actions are unlocked.

Troubleshooting

            

              

                
ProblemSolution

                
                  
Browser doesn't open automaticallyOpen http://127.0.0.1:8080 manually (or the port shown in terminal). A second instance points to the running one.

                  
"Check all managed apps" fails with "Failed to load config"Run "Check All Updates" again. The endpoint is public; if auth is required, add a GitHub token first.

                  
Update column always shows "-"Run "Check All Updates" to populate update_available state. New version appears as "Update available → vX.Y.Z".

                  
Install button does nothingConfirm the action in the dialog. Check the loading overlay — requests are serialized to prevent duplicates.

                  
Uninstall reports success but app remainsohub now removes the download/staging folder after uninstall. Some installers leave files behind; remove them manually if needed.

                  
Config fields are lockedohub is running with --auth and you don't have a token. Sign in or add a GitHub token.

                  
Login fails with "PowerShell is not available"Use "Use GitHub token" instead, or run ohub config set github_token <token>.

                  
"ohub webui" won't start — another instance runningohub reports the existing PID and opens the existing WebUI URL in your browser.

                
              

              
Still stuck? Run ohub doctor from the Doctor page, or export state via State Export and file an issue at GitHub Issues.
